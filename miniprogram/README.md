# APRS 动画部 · AnimFlow

RPG 委托主题的动画制作协作微信小程序，服务于 **APRS艺术生产力研究实验室** 下辖的动画部门。部门管理员张贴制作委托，工作者接取、推进并提交验收，形成一条可演示的完整委托流。

> 当前版本为**本地演示模式**：委托数据保存在当前设备的微信本地缓存中，不依赖服务器。身份切换、委托流转和验收闭环都可直接体验。真实的多设备协作需要接入云开发或自建后端，方案见 [docs/backend-roadmap.md](docs/backend-roadmap.md)。

## 主题与美术方向

- **暮色工坊**：深色木质与皮革底色，羊皮纸卷轴、金色描边、蜡封红和幽绿点缀。
- **委托告示栏**：告示栏是主看板，委托卡是挂在栏上的羊皮纸卷轴，带工序徽记与悬赏星级。
- **角色化双端**：管理端 = 部门管理员（张贴 / 指派 / 验收），工作者端 = 工作者（接取 / 提交 / 查看批注）。
- **RPG 信息层级**：委托编号 `№`、卷宗场次、悬赏等级 `★`、赏金金币、工作日志时间线、部门批注。
- 纹理、描边、角饰、蜡封和图标全部由 WXSS 渐变 / 边框与本地 PNG 构成，无外部图片和第三方 UI 库。

## 生产阶段与工序

工作者端按 **前期 → 中期 → 后期** 两级筛选可接取委托：先选大阶段，再选具体工序。

| 阶段 | 具体工序 |
| --- | --- |
| 前期 | 策划、剧本、分镜、美术设计、Layout |
| 中期 | 原画、原画监督、清线、中割、中割检修 |
| 后期 | 上色文件输出、色指定检查、色指定执行、上色、上色层导出、线稿层导出、特殊层导出、场景绘制、影像合成、特效、配音、音效合成、成片输出 |

> 按制作顺序，原画与原画监督排在 Layout 之后、清线之前，归入中期作画阶段。阶段与工序的对应关系集中在 [utils/constants.js](utils/constants.js) 的 `STAGES` 与 `PROCESSES` 中，调整顺序或增删工序只需要改这一处。

## 项目立项与任务量

管理员从「立项」进入项目页，输入项目名称后，系统会按上述 23 个工序自动生成完整任务链。每项任务都可以修改标题、说明、工作量和单价，也可以取消「纳入项目」跳过某一项。

| 计量方式 | 适用工序 |
| --- | --- |
| 一次性（项） | 策划、剧本、美术设计 |
| 绘画张数（张） | 分镜、Layout、原画、原画监督、清线、中割、中割检修、上色文件输出、色指定检查、色指定执行、上色、上色层导出、线稿层导出、特殊层导出 |
| 时长（秒） | 影像合成、特效、成片输出 |
| 场景个数（个场景） | 场景绘制 |
| 字数（字） | 配音 |
| 音效素材数量（条） | 音效合成 |

- 任务赏金 = 工作量 × 单项单价；一次性工序的工作量固定为 1，单价即总价。
- 系统会给出一组可编辑的默认工作量和单价，管理员按项目实际情况调整。
- 发布后项目名称和整体期限锁定，但任务内容、工作量、单价仍可修改；已接取该项任务的工作者会收到看板变更通知，任务日志也会留下更新记录。
- 项目详情底部可以归档整个项目，未完成任务会取消，项目、任务与工作日志全部保留，已接取的工作者会收到取消通知。
- 单个任务也可以在任务详情中取消；取消后任务保留为「已取消」，不再允许接取或提交，项目总赏金会重新计算。
- 项目任务会直接进入工作者端的告示栏，与普通委托共用接取、提交验收流程。

### 已包含的细节

- 首次进入按「选择身份 → 登记 QQ / 昵称 → 管理者校验秘钥」完成登记；已有资料的 QQ 会直接登录。
- 同一 QQ 可分别登记一次部门管理员身份和一次工作者身份，重复登记会被拦截。
- 项目立项自动生成 23 个工序，可逐项修改内容、工作量与单价，支持发布后继续修改并通知接取人。
- 全新安装时任务、资料与项目均为空，管理员立项后才会生成 23 个工序任务。
- 阶段 / 工序两级筛选：前期、中期、后期各带数量，进入阶段后再按具体工序筛选。
- 委托状态：`待接取 → 进行中 → 待验收 → 已归档`，退回后回到进行中，可再次提交；未归档任务可被管理员取消，进入 `已取消`。
- 管理员可从任务详情取消单个任务，或在项目详情归档整个项目；已接取的工作者会收到取消通知。
- 已归档项目集中在项目列表的「已归档项目」入口；归档时未完成任务会保留「招揽中 / 进行中 / 待验收」的归档前状态。
- 归档库支持单个项目「清除此项目」与「彻底清除全部归档」，会删除对应任务、通知和排行结算记录，不影响进行中项目。
- 工作日志时间线、部门批注、逾期提示、悬赏星级、赏金、接取人。
- 资料页可展开成员，查看昵称、QQ（仅管理员可见）与其已接取委托明细。
- 月度排行按验收时间归月，统计已归档委托的结算赏金、任务量与工作量构成，切换月份可查看历史榜单。
- 管理员可取消 / 恢复工作者的任务执行权；停用会释放其进行中与待验收委托，删除资料会同时移除账号与通知。
- 自定义导航栏、刘海屏安全区适配、下拉刷新、空状态、加载骨架、Toast、触感反馈。
- 原生 tabBar（委托 / 排行 / 资料）与六枚 RPG 风格图标。
- 无第三方运行时依赖，直接使用微信小程序原生 WXML/WXSS/JS。

## 运行方式

1. 打开微信开发者工具。
2. 选择「导入项目」，目录指向 `D:\work_district`（本项目根目录，包含 `app.json`）。
   如果开发者工具里已经打开了该目录，直接点「编译」即可。
3. AppID 可使用默认的 `touristappid` 进行本地体验；如需真机预览，填入自己的小程序 AppID。
4. 点击「编译」。如果首次进入没有会话，会自动落到身份选择页。

无需执行 `npm install`。项目没有 miniprogram_npm 依赖，也不依赖云开发环境。

## 建议体验路径

1. 选择「部门管理员」，输入 QQ、昵称和管理员秘钥 `APRS1023` 完成首次登记，进入委托告示栏。
2. 点击「＋ 立项」，输入项目名称后系统自动生成 23 个工序；逐项调整工作量和单价，点击「发布项目」。
3. 也可以在告示栏点「＋ 委托」张贴单张委托：
   - 填写委托标题、工序、悬赏等级、卷宗场次、交付期限、赏金和详情；
   - 选择「公开张贴」或「指定工作者」；
   - 张贴后回到告示栏。
4. 进入「资料 → 切换身份」，选择「工作者」并登记 QQ / 昵称；已有资料的 QQ 会直接进入。
5. 在「可接取」中先选择前期 / 中期 / 后期，再选择具体工序，接取一份公开委托，完成后点击「提交验收」。
6. 切回部门管理员，在「待验收」的委托详情页：
   - 填写批注后「退回修改」；或
   - 直接「验收通过」。
7. 管理员在「立项 → 项目详情」修改已发布任务的工作量或单价，工作者看板会出现变更通知。
8. 切回工作者查看部门批注、变更通知与工作日志。

「资料 → 清空工作台数据」会清空所有任务、项目与变更通知，恢复为空工作台。

### 初始状态

全新安装不包含任何示例任务、示例资料或示例项目。先选择「部门管理员」用秘钥 `APRS1023` 登记，再登记工作者，或者直接立项。

> 秘钥和账号校验目前都在本地执行，仅用于演示；接入服务端后必须改为服务端校验。

## 架构说明

```
页面(Page)
   ↓ 登记 / 登录
AccountStore
   ├─ QQ + 角色作为唯一账号
   ├─ 同一 QQ 最多一个管理员、一个工作者
   └─ 昵称、QQ、头像、岗位
   ↓
TaskService
   ├─ 校验角色 / 状态 / 必填项
   ├─ claim / submit / review 状态流转
   ├─ 组装告示栏、筛选、统计、卷轴视图模型
   └─ 写操作立即持久化
ProjectService
   ├─ buildDraftTasks：按 23 个工序生成任务草稿
   ├─ publishProject：一次性创建项目与全部任务
   ├─ updateProjectTask：修改内容 / 工作量 / 单价
   └─ 已接取任务变更时写入 NoticeStore
Store（当前）
   ├─ TaskStore / ProjectStore / AccountStore / NoticeStore
   └─ wx.setStorageSync / wx.getStorageSync
```

页面只消费已经「装饰」好的委托对象，包括：

- `stageKey / stageName / stageShort / stageColor / stageSoft / stageOrder`
- `processKey / categoryName / categoryEn / categoryColor / categorySoft / categoryShort`
- `projectName / workload / workloadQuantity / workloadUnitLabel / unitPrice / workloadSummary`
- `statusName / priorityName / priorityRank / priorityStars`
- `dueLabel / dueTone`
- `action / actionLabel / isActionable`
- `logs[].timeLabel / actorInitial / actorColor`

看板接口接收 `getBoard(actor, { filter, stage, process, keyword })`，返回 `stages`、`processes` 以及当前选中的 `activeStage / activeProcess`，页面只负责渲染。因此后续替换服务端时，页面层几乎不需要改，只需要让远端结果继续返回相同字段。

### 账号与资料

- 账号以 `QQ + 角色` 为唯一键，`services/accounts.js` 负责注册、查询与校验。
- 首次登记需要昵称（2-12 字）和 QQ（5-12 位数字）；管理员还需要 `APRS1023` 秘钥。
- 已有资料的 QQ 再次进入时会跳过登记，直接登录；同一 QQ 也允许登记另一种角色一次。
- 资料页的 QQ 只对管理员返回；工作者端拿到的 `qq` 字段为空。
- 当前账号、秘钥校验都在本地，属于演示实现；真实环境必须放到服务端，防止客户端伪造。

### 视觉层约定

- 全局底色 `#17120D`，羊皮纸 `#F7ECD6 → #E7D2A9`，金色 `#D9B45B / #E8C378`，蜡封红 `#A6402F`，工坊绿 `#3F5D4A`。
- 卡片使用双层描边、顶部金线与右下角饰角；告示栏总览带内框和菱形钉饰。
- 标题使用宋体 / Songti 回退栈，正文使用系统无衬线字体。
- 各页面的 `rise-in` 入场动画与骨架屏 `shimmer` 保持统一节奏。

### 权限与状态规则

- 只有 `role === 'admin'` 可以张贴、指派、验收委托，以及立项、修改项目任务、管理人员资料。
- 只有 `role === 'employee'` 可以接取和提交委托；执行权被停用的工作者会被拒绝登录与操作。
- 接取：仅 `status === 'open'` 且没有接取人的委托。
- 提交：仅接取人本人且委托为 `in_progress`。
- 验收：仅部门管理员且委托为 `in_review`；退回必须填写批注。
- 修改已发布项目任务时，如果已有接取人，会为其生成一条变更通知。
- 取消任务仅管理员可操作，且只能取消未归档、未取消的任务；已取消任务保留记录，但不可再接取或提交。
- 归档项目仅管理员可操作，项目转为只读，未完成任务取消，项目、任务与工作日志全部保留，并通知已接取的工作者。
- 「彻底清除归档」仅管理员可操作，支持单个项目或全部归档；只删除 `archived` 项目及其任务、通知和排行记录，不影响进行中项目。
- 取消执行权会释放该成员进行中 / 待验收的任务；删除资料会移除账号、通知和登录能力，已归档记录保留。
- 月度排行按 `completedAt`（验收通过时间）归入月份，结算金额为已归档委托的 `reward` 之和；已删除成员的已完成记录仍保留在历史榜单。
- 所有写操作都会追加工作日志，并更新 `updatedAt`。

## 本地数据与限制

- 存储 key：`animflow:accounts:v1`、`animflow:tasks:v1`、`animflow:projects:v1`、`animflow:notices:v1`、`animflow:session:v2`、`animflow:last-qq:v1`；任务数据版本 `5`。本版会清空旧版本本地缓存（含示例数据）。
- 「清空工作台数据」会清空所有任务、项目与变更通知，账号资料保留。
- 账号资料保存在当前设备；清除小程序缓存会同时清除已登记的管理员/工作者身份。
- 成员账号带执行权状态；停用可恢复，删除资料不可撤销（该 QQ 可重新登记）。
- 工作者 QQ 仅管理员可见；管理员可在资料页展开成员查看其已接取任务。
- 数据存在当前设备、当前微信账号下，**不会自动同步到另一台设备**。
- 两个身份共用同一份本地委托数据，因此可以在单机上完整演示「立项 → 接取 → 修改通知 → 验收」。
- 变更通知是本地应用内通知（看板横幅 + 任务日志），不是微信订阅消息。
- 已加入基础校验，但本地存储不具备服务端事务能力；真实并发接取需要服务端条件更新或事务。
- 没有实现账号密码、真实登录、附件与云端文件存储。
