# ARPS制作工会 · 核心设计逻辑

这一页讲**为什么这样设计、哪些规则不能随便改**。细节和验收标准在 [SPEC.md](SPEC.md)，代码里的「SPEC §N」指那份文件的章节。

> **main 分支就是核心设计逻辑的正本。** 规则以 main 上的 `docs/` 和 `src/domain/` 为准。想改一条规则，先在同一个提交里改文档，再改代码和测试；其他分支上的改动，合进 main 之前都不算数。

## 一句话

一个带游戏感、但不花哨的动画 / 视频制作工会任务板。工作被拆成「卡 × 环节」的任务格：成员报到一个环节 → 系统自动配一张任务单 → 交 → 审核 → 通过的格子点亮、下游解锁 → 按必要劳动时间记活力点。所有人都能看到整体进度，也能在任何一格留意见。

三条总要求：**流程化**（环节表 + 指示器）· **制度化**（报到 → 配任务 → 时限 → 审核 → 收回）· **可视化**（环节路线 · 交付物墙 · 成长与活力点）。

## 1. 工作的单位：卡 × 环节 × 层

- **卡**是镜头（C001…），一卡有 A / B 等层，每层若干张。**环节**是流程里的一步（Layout、原画、中割……）。一格 = 一卡在一个环节（分层的环节再分到层）上的一件事，就是一张**任务**。
- 看的时候分三层，一层只管一件事：**项目**（环节路线：走到第几个环节、哪里已经结束）→ **环节**（谁在做、派了什么、交了什么，就地改）→ **卡 / 任务**（具体一版）。不做一个「改项目」大表。
- 项目从**零日**开始（只有介绍、日期、结构、人员，不生成任务），点「开工」才按模板生成环节、卡和任务。开工后环节一个接一个亮起来。

## 2. 流程是数据，不是代码

- 流程模板在 `src/domain/templates.ts`，是纯数据：每个环节有 阶段（前期 / 中期 / 后期）· 类型 · 粒度（项目一份 / 每卡一份 / 每卡每层一份）· 单位 · Tn · 文件代码 · 上游 · 指示器文案（收什么、交什么、交到哪、交给谁）。
- 三种环节类型：**过渡**（一进一出）· **枢纽**（算出后面的工作量并派发，或几路汇合）· **审核**（本身就是检查，可以锁成只给指派的人）。
- **连线推进**（`src/domain/flow.ts`）：上游全部通过 → 下游同一卡的任务从「锁住」变「可接」。解锁和那次审核写在**同一条日志**里。
- 管理员能加 / 插 / 改 / 停用环节，能改工时和时限参数；有交付的环节只能停用，不能删。

## 3. 制度：任务从哪来、到哪去

- **报到 = 自动配任务**：报到一个环节，立刻按卡号顺序配一张（不超过同时手上的上限）。成员也能自己认领别的环节的可接任务；管理员也能直接指派。
- **时限** = 工作量 × Tn × 时限系数（默认 1.5，最少 4 小时）。超时没交，打开时自动收回到可接，记一条。
- **交** = 版本号 +1，文件名按命名规范自动生成，链接或说明至少一个。
- **审核**：通过（选质量系数 0.5 / 1.0 / 1.2）/ 退回（意见可写层、张号、标签，也可以钉在图上）/ 自修后通过（审核员自己修出一版，记在审核员名下）。每个环节都要终审；环节全部通过后由管理员**验收**，也可以挑几卡打回重做。
- 任何节点上都能**随时发新任务**（额外任务 · 修正 · 补设定）。默认不挡流程，勾了才挡这一卡的下游。
- 设定问题要有人**拍板**；拍板后列出的卡各自自动留一条「要补」。

## 4. 活力点：公开、同一套算法

- **活力点 = 必要劳动时间 Tn × 工作量 ×（掌控系数 + 熟练度）× 质量系数**，在审核通过那一刻按当时的参数算好、落进流水（`ledger`）。
- 审核台在通过之前就把算式摆出来。等级、经验条、准时率、合作关系都从任务和流水算出来，不另外存。
- 盘点时补录的旧版本，默认不记人、不记活力点。

## 5. 数据层：命令 → 变更集 → 只追加的日志

- 写只有一条路：`dispatch("命令名", 输入)` → 命令读 ReadModel、检查、产出变更集 → apply → 追加一条日志。**读**只用 `src/domain/queries.ts` 里的查询。页面里不遍历表、不拼业务规则。
- 日志能从头**重放**出整个工会（示范工会也是从空世界一步一步跑命令建出来的）。每条命令之后都能做完整性检查。
- 命令被拒时返回 `code + key + 参数`（`src/domain/errors.ts`），界面按语言拼成句子。
- ID 是 `<前缀>_<UUIDv7>`。时间一律走 `clock.ts`（世界时间可以冻结）。排序只比 ASCII 的东西（`agenda.ts`），不用 `localeCompare` 比显示文字。

## 6. 本地优先，以后再接服务器

- 整站是静态的。数据存在浏览器里：每个工会一个键（`arps:w:<id>`），文件存在 IndexedDB（按内容 SHA-256，同一个文件只存一份）。断网能开，也能导出 / 导入备份（可以连文件一起）。
- `pnpm build:single` 打成**一个 HTML 文件**，发到群里下载就能用。
- 以后接主服务器只换存储那一层：`src/lib/sync` 的 `SyncAdapter`（`push(entries)` / `pull(afterSeq)`），本机实现和 HTTP 实现都在。服务器端会用同一套纯函数命令重跑（SPEC §14.4）。
- 现在的口令只是同一台设备上的**软锁**（只存 salt + 哈希），不是安全登录。

## 7. 命名规范和交付物盘点：先认名字，再看图，最后人拍板

- 文件名规范：`[项目]_[集数]_[场景]_[镜头]_[层级]_[流程]_[版本]`，例 `ANDLC_EP01_SC001_CUT005_A_ANI_v04`；文件夹 `/EPxx/<流程>/SCxxx/CUTxxx/`。改了不覆盖，版本号 +1。
- **盘点**（`src/domain/audit/`）：把已经交了的文件（拖文件夹 / 粘贴文件名列表 / zip 目录）读进来 → 按 `_` 切段、按样子认每一段，说清楚哪里不对 → 和系统里记的对一遍（对上了 · 有文件系统没记 · 系统说交了没找到 · 文件比系统新 · 缺）→ 人看图复查 → 人确认后才写回（核实 / 补录 / 打回 / 加卡），整批能撤销。**自动的只提示，不替人改项目。**
- CSP 的 `.clip` 文件尾部有一个 SQLite 块，里面带整张画面的预览图、画布、帧率、时长。程序只读这一块（自己写的只读 SQLite 读取器），不读整个大文件，默认也只存名字和缩略图。
- 看项目以图为主：交付物墙（每格最新一版的缩略图 + 状态角标，缺的画斜线）、环节路线上的缩略图条、卡详情的胶片条、「还差多少」。每一版只显示它自己的图，没有就写「没有图」。

## 8. 视觉和语言

- 游戏感从**结构**来，不从装饰来：任务单像任务卡（黑卡、大号倒计时、奖励数字）、报到像选职业、环节路线像关卡。不用循环动画、发光、渐变、撒花、贴纸。
- 只用 `src/styles/tokens.css` 的变量。状态都用 字 + 颜色 + 图形 一起表示，不只靠颜色。
- 中文 / English 两套词典（`src/i18n`），键名一样，少一个键编译不过。用户写的内容（项目名、昵称、意见）不翻译。

## 不能破的规矩

1. 读用查询，写用命令；命令名会记进日志，是稳定的接口，改名要写迁移。
2. 时间走 `clock.ts`；排序走 `agenda.ts`，不用 `localeCompare` 比显示文字。
3. 示范数据只在 `src/data/demo.ts`；示范里的人名全部是编的；真实作品和真实文件不进仓库（测试用脚本生成的假文件）。
4. 口令、密钥不进仓库；账号只存 salt + 哈希；测试从环境变量读口令。
5. 合进 main 之前：`pnpm typecheck` · `pnpm test` · `pnpm build` · `pnpm build:single` · `pnpm smoke` 全绿。main 上不 reset、不 rebase、不强推。
