# ARPS制作工会 · 规格

这是产品规格：程序为什么这样做、规则是什么。代码注释里的「SPEC §N」指的就是这份文件的章节。核心设计逻辑的一页版见 [DESIGN.md](DESIGN.md)。

## 0. 一句话

一个带游戏感的工会任务板：管理员开项目 → 项目按组（动画 / 视频）套流程模板，拆成「卡 × 环节」的任务格 → 成员报到某个环节，系统自动配一张任务单 → 交上来（飞书链接 + 规范文件名 + 版本号）→ 审核员通过 / 退回 / 自己小修再出一版 → 通过的格子点亮，指示器告诉下一个环节「去哪收、交到哪、给谁」→ 每一步按「必要劳动时间」记活力点，人有等级和成长。所有人都能看整体进度，并在任何一格、任何阶段留意见。

三条总要求：**流程化**（环节表 + 指示器）· **制度化**（报到 → 配任务 → 时限 → 审核 → 收回）· **可视化**（三段进度 · 卡 × 环节总览 · 成长与活力点）。

## 1. 真实工作是怎么跑的

- 单位是**卡**（镜头，C001…C014）。每卡分 **A / B 层**，每层若干**张**（帧）。工作按「卡 × 环节」分派，例如「C009 中割：某人」。
- 文件名规范（v1.0）：`[项目]_[集数]_[场景]_[镜头]_[层级]_[流程]_[版本]`，例 `ANDLC_EP01_SC001_CUT005_A_ANI_v04.clip`。流程代号：LAY · LO · H（原画）· ANI（中割）· CLN · CMP · FIN。改了不覆盖，版本号 +1；进下一环节前上一环节的最终版锁定。文件夹 `/EPxx/<流程>/SCxxx/CUTxxx/`。
- 一卡在一个环节里会来回好几版：成员交 v02 → 监修指出问题（截图 + 「A 层第 6、7 张」「第 18 张下巴漏色」）→ 成员改「v02 第一次修改后」→ 监修自己修掉小问题出 v03 → 通过。**监修可以自修出版本**，这一版算在监修名下。
- 问题经常要问**上游**：中割问原画「第 4、5 张之间有中割标记，轨目漏了」→ 原画解释轨目怎么读。也会问**设定**：「箭头影要不要加，是沿用第 9 卡的设定吗」——这种要有人拍板，拍板的结果之后所有卡都要照着补（「5、7、9、10 卡要补耳饰」）。
- **交接**：监修完成 → 发给「文件导出」的人 → 他把线稿、色彩、特殊分层单独导出，整理成一个文件夹 → 后期。统筹常问「1–14 有哪些已经交到导出了」「要尽快了」。
- 大文件常走 QQ 闪传 / 群文件，会过期；统一放到飞书这类长期能打开的地方，系统只存链接。
- 常见退回原因：漏色 · 色线缺失或不闭合 · 背涂填错图层 · 背涂涂到主线 · 主线不透 · 分层错误 · 涂反 · 漏轨目 · 设定没补。
- 计分（活力点 = 工分）：**活力点 = 必要劳动时间 Tn ×（掌控系数 + 熟练度系数）× 质量系数**。Tn 标准：导演 / 监制 0.5h / 卡 · 剧本与分镜 4h / 15 秒 · 设计稿 LO 2h / 张 · 原画 3h / 张 · 中割 / 清线 1.5h / 张 · 上色 0.2h / 张 · 后期 / 摄影 1.5h / 10 秒。熟练度 +0.5 / +0.2 / 0 / −0.2；质量 0.5 / 1.0 / 1.2（审核时选）。目的：分配公平、过程公开、外来成员也能按同一套规则定价。先只记虚拟积分，不结算钱。

## 2. 角色

| 角色 | 能做什么 |
|---|---|
| 管理员 | 开项目（定组、代号、集 / 场 / 卡数、每卡张数和秒数）；改流程模板的工时和系数；在**枢纽环节**填工作量并一键生成任务；指定审核员；拍板设定问题；收回任务；看全部 |
| 审核员 | 审任务：通过（选质量系数）/ 退回（带意见，每条可写层和张号、打标签）/ 自修出新版后通过；也能自己接任务。原画监督、中割检修这类环节本身就是审核性质，可以由审核员担任；**有时外包**：任务可以标「外包」，交的人不在工会里，由管理员代交 |
| 成员 | 报到一个或几个环节（选熟练度）→ 自动拿到任务单；交 / 放弃（返还）/ 提问 / 留意见 |

同一台设备上可以切换身份（第一版 = 方案 A：一台设备跑通，管理员可以代录；以后接主服务器，每人用自己的手机）。

## 4. 数据（命令 → 改动 → 日志；读用查询；ID `<前缀>_<UUIDv7>`）

| 表 | 关键字段 |
|---|---|
| `members` | 昵称 · 角色（admin / reviewer / member）· 加入时间 · 头像色 |
| `enrollments`（报到） | 成员 · 组 · 环节 key · 熟练度（+0.5 / +0.2 / 0 / −0.2）· 同时最多几张（默认 2） |
| `projects` | 组 · 名字 · 代号（2–6 位大写）· 集 / 场 · 开始 / 计划结束 · 状态 · 飞书根文件夹链接 |
| `stages`（项目里的环节，从模板生成） | 项目 · 模板 key · 阶段 · 类型 · 粒度 · 单位 · Tn · 上游 key 列表 · 指示器文案 · 审核员 |
| `cuts`（卡） | 项目 · 集 · 场 · 卡号 · 层（A / B …）· 每层张数 · 秒数 |
| `tasks` | 项目 · 环节 · 卡?（项目级为空）· 层? · 工作量 · 状态（**锁住**：上游没完 · **可接** · **已接** · **待审** · **退回** · **通过** · **收回**）· 接的人 · 接的时间 · 时限 · 外包? |
| `submissions`（版本） | 任务 · 版本号 · 规范文件名（系统按规范生成，可改）· 飞书链接（只收 http/https）· 说明 · 谁交的（可以是审核员自修）· 时间 |
| `reviews` | 任务 · 版本 · 结论（通过 / 退回 / 自修后通过）· 质量系数 · 意见（若干条：层? · 张号? · 标签? · 文字）|
| `threads`（意见 / 提问） | 挂在：卡 · 任务 · 项目；类型（意见 · 提问上游 · 设定问题）· 问谁（环节或人）· 状态（开着 / 已答 / 已拍板）· 回复 |
| `rulings`（拍板） | 项目 · 问题 · 结论 · 要补的卡（自动在这些卡上留一条「要补」） |
| `ledger`（活力点流水，可以从日志算，也可以落表） | 成员 · 任务 · Tn × 工作量 × 系数 · 时间 |

规则：

1. 上游任务全部「通过」→ 下游同一卡的任务从「锁住」变「可接」（`flow.ts`：在同一个变更集里把下游叫醒）。项目级枢纽 → 下游每卡的任务都解锁。
2. **报到 = 自动配任务**：报到完立刻从这个环节「可接」的里面按卡号顺序配一张（不超过上限），弹出任务单。「接任务」按钮再配一张。
3. 时限 = 工作量 × Tn × 系数（默认 1.5，管理员可改；先设立后修改）。过了时限没交 → 打开时自动「收回」到可接，记一条；扣不扣成长分做成开关，默认不扣。
4. 放弃 = 返还到可接，不扣分。
5. 交 = 新版本号 +1；文件名按规范自动生成；必须有链接或说明其一。
6. 审核：退回 → 回到原来的人手上（状态「退回」，显示意见清单，改完再交）；通过 → 记活力点（交的人；自修的那一版另记给审核员 0.5h × 卡）；每个环节都要终审。
7. 设定问题拍板以后，列出的卡各留一条「要补」意见，相关任务卡上显示。
8. 活力点 → 经验；等级 Lv = 按累计活力点分段（10 · 30 · 60 · 100 · 150 …，写成表）。准时率 = 时限内交的 / 交过的。协作关系 = 和谁在同一卡上做过事（从任务算）。长期归属 = 加入天数 + 主环节（做得最多的）。
9. 时间一律走数据层时钟；排序不用 `localeCompare` 比显示文字。

## 6. 视觉（要有游戏感，但千万不要花里胡哨）

设计系统 v0.3.1（代码里 `src/styles/tokens.css` · `typography.css` · `src/components/ui`）：

- 暖沙色画布、无边框白卡（圆角 32）、靠底色分层不靠阴影；黑卡每屏最多 1–2 张，给「现在这件事」（当前任务单）。
- 主操作是鼠尾草绿胶囊（Accent）；可点的都是胶囊；颜色不单独表意，状态都带字。
- 字：Noto Sans SC + Outfit（数字）；中文最小 12px。
- **游戏感从结构来，不从装饰来**：任务单像任务卡（黑卡 · 大数字倒计时 · 奖励「+12.0 活力点」）；等级用细经验条和 Lv 数字；三段流程像关卡地图（节点 + 连线，用 `workflow/edge` 的变量）；报到像选职业（职业卡的选中态）；通过时一次性的小提示（不循环动画、不撒花、不发光、不渐变、不加贴纸）。
- 状态色：锁住（surface-muted + 灰字）· 可接（accent sky）· 已接（accent sand / peach）· 待审（status warning-bg）· 退回（status danger-bg）· 通过（status success-bg）· 收回（灰）。

## 10. 账号

- 两个账号预先建好：`admin`（工会管理员，角色 admin）· `member01`（成员 01，角色 member）。登录 = 选账号 + 输口令。
- **仓库里只存 salt + SHA-256 哈希**（`src/data/accounts.public.json`），校验 `sha256(salt + ":" + 口令)`，用 WebCrypto `crypto.subtle.digest`。口令原文**不进仓库、不进示范数据、不进测试文件**；测试从环境变量 `ARPS_PASS_ADMIN` / `ARPS_PASS_MEMBER` 读，没设就跳过要口令的那几项。
- 这是**本机的软锁**（同一台设备上切换身份要输口令），不是真正的安全：静态网页、数据在浏览器里，懂技术的人能绕过。真正的登录等接主服务器（§14.4 的签名 Cookie）。界面上不要写成「安全登录」。
- 管理员能在「管理」里改自己的口令、给新成员建账号（同样只存哈希）、重置别人的口令。
- 两个账号都登录进同一个「示范工会」；`admin` 对应编的「白鹭」，`member01` 对应编的「木星」（中割）。

## 8. 「网页 + 本地」

- 本地：整站是静态的，浏览器里存（每个工会一个键，前缀 `arps:`），能装到桌面 / 手机主屏幕，断网能开。
- 网页：同一份代码部署到 Vercel；以后接主服务器时只换存储那一层：留一个 `SyncAdapter` 接口（`push(entries)` / `pull(afterSeq)`），本机实现 + 一个 HTTP 实现（§14.4 的形状）（有测试，界面上不放用不了的「连接」按钮）。
- 单文件版：要能打成**一个 HTML 文件**，下载下来用浏览器打开就能用，断网也行。

## 9. 硬规矩

- 读用查询、写用命令；页面里不拼业务规则、不直接读写 localStorage。
- 时间一律走数据层时钟；排序不用 `localeCompare` 比显示文字。
- main 上不 reset / rebase / 强推。
- 密钥、口令不出现在仓库、示范数据、测试里。
- 示范数据里的人名全部是编的；真实作品和真实文件不进仓库。

## 11. 资料库：离线的文档和图片管理

要解决的问题：断网时它至少是一个能预览、能评论的文档和图片管理器，像一个以图片为主的 Notion。工会现在的做法：截图（局部放大 + 红圈 / 箭头）+「A 层第 6 张」+ 一句话 → 对方改 → 再传。

### 11.1 存什么、存哪
- **文件本身**（图片、PDF、.clip、.rar、视频……任何类型）存在浏览器的 **IndexedDB**（库名 `arps-files`，按内容的 SHA-256 存，同一个文件只存一份）；localStorage 只有 5MB 放不下图。断网照样能看。
- **文件的信息**走命令和日志（和别的数据一样能导出、能重放）：`file.add`（id · sha256 · 文件名 · 类型 · 大小 · 图片的宽高 · 一张 ≤ 20KB 的小缩略图 dataURL · 挂在哪：项目 / 卡 / 任务 / 版本 / 资料页 · 标签 · 谁传的）· `file.rename` · `file.tag` · `file.move`（换挂的地方）· `file.archive`。
- 存储页显示两部分用量（浏览器里的记录 + 文件），用 `navigator.storage.estimate()` 算 IndexedDB 的部分；快满时提示。

### 11.2 放进来
- 三种办法都要有：**拖进来** · **点「添加文件」选** · **直接粘贴截图**（Ctrl/⌘+V，最常用）。多选、多文件一次放。
- 放到哪里：项目的资料库（可以选卡 / 环节 / 标签）· 卡详情 · 交一版时（除了飞书链接，还能附截图 / 导出的胶片预览）· 资料页 · 评论里。

### 11.3 看
- **资料库页**（每个项目一个，侧栏有入口）：缩略图网格（图片为主，非图片文件显示文件卡：类型 · 大小）；按 卡 · 环节 · 类型 · 标签 · 谁传的 筛；按时间排；搜文件名。
- **看图器**（点任何一张图打开，全屏层）：放大 / 缩小 / 适应 / 拖动（鼠标滚轮、触控板、手机双指、按钮都行）；左右切换同一组的图；**版本对比**：同一卡同一环节的两版并排（或滑块左右对比）；看文件信息。
- **非图片**：PDF、.clip、.rar 等显示文件卡（名字、类型、大小、谁传的、挂在哪），能「保存到这台设备」；PDF 先不做页面预览（可以晚点）。

### 11.4 评论（最要紧）
- 在图上**点一下 = 放一个编号的钉**，**拖一下 = 框一个区域**，然后写意见；可以选 层 · 张号 · 退回标签（§1 那几种）。钉和框按图的比例存（缩放后还在原处）。
- 每个钉是一条讨论：能回复、能「解决」（解决的变灰，可以隐藏）。看图器侧边列出这张图所有钉；点列表跳到那个钉。
- 图上的评论同时出现在：这张图挂着的卡的时间线 · 相关任务的「等我处理」（钉里 @ 了谁，或者是在审核退回时加的）。
- 审核员退回时可以直接附图并在图上钉（相当于截图 + 红圈那一步）。

### 11.5 资料页（像 Notion，但以图为主）
- 每个项目能建若干资料页（例：设定集 · 色指定表 · 文件命名规范 · 后期流程规范）。页面由块组成：标题 · 段落 · **图片（单张 / 多张网格）** · 文件 · 清单 · 分割线。能加块、删块、上下移动、改字。图片块点开就是看图器，能钉评论；每个块也能留评论。
- 命令：`page.create` · `page.rename` · `page.archive` · `block.add` · `block.update` · `block.move` · `block.remove`（块的内容存在日志里；图片块只存文件 id）。
- 示范工会里放三页：「设定集」（人物设定图 3 张，图上有 2 个钉，一个已解决）· 「文件命名规范 v1.0」（照 §1 的规范写成文字块）· 「后期流程规范」（照 §1 的分工写成清单）。

### 11.6 导出 / 导入 / 下载
- 导出备份时可以勾「连文件一起」：文件转成 base64 放进同一个 JSON（文件多时先提示大小）；不勾就只导记录，导入后缺的文件显示「这个文件不在这台设备上」的占位，再把文件拖进来就能对上（按 SHA-256 认）。
- 「复制 / 粘贴备份」只带记录，不带文件（写清楚）。
- **下载**：在嵌入式预览页面里（例如 claude.ai 的 Artifact），普通下载会被挡住。先试 `const dl = await window.claude?.use?.("downloads")`（拿到 null 或 10 秒没回就当没有），有就用 `await dl.save({ filename, data })`（data 可以是 Blob；扩展名只允许 `json png jpg jpeg webp gif pdf zip txt md csv svg mp4 webm`，别的类型如 .clip/.rar 在预览页面里提示「在这里存不了这种文件，请在装好的版本里下载」）；被拒（`declined`）不重试。没有就用普通的 `<a download>`。只在用户点按钮时调用。
- 示范数据里的图片**不用真实作品**：用代码画的线稿占位图（SVG，像人物线稿 / 分层色块，标「示范图」），用户自己把真图拖进来。

### 11.7 验收（加进冒烟）
拖 / 选 / 粘贴各放一张图 → 资料库里看到缩略图 → 打开看图器放大、拖动 → 点一下放钉写意见、拖一下框一块写意见 → 回复 → 解决 → 卡时间线上能看到 → 两版对比 → 资料页加一个图片块和一个段落、上下移动 → 断网刷新图片还在 → 带文件导出再导入（新浏览器环境）图片还在 → 375 宽能用 → 控制台 0 报错。

## 12. 管理员改项目 · 零日

要解决的问题：管理员要能编辑项目本身——设立 / 增加环节、检查交付物、把关最终成果；哪里不过，可以给那里加时间或加卡。项目开工前有一个「零日」状态：写介绍和日期、填人员，有模板项目可以照着开局。

### 12.1 零日（项目开工前的样子）
- 项目多一个状态「**零日**」（筹备，还没开工）：建项目先进零日，**不生成任务**；管理员点「开工」才按模板生成环节、卡和任务（`project.start`）。示范工会已有的两个项目都是开工后的；另放一个零日的例子项目「（模板）动画短片」给大家看怎么开局。
- 零日页（就是项目的「封面」，开工后也一直能看、能改）：
  - **项目介绍**：名字 · 代号 · 组 · 一段介绍（几句话：讲什么、多长、给谁看）· 封面图（从资料库选一张，可以没有）
  - **日期**：开始 · 计划结束 · 一周期几天（默认 7）· 几个关键日（例：分镜定稿 · 原画完成 · 交片；名字和日期都能改、能加）
  - **结构**：几集 · 每集几场 · 每场几卡 · 每卡几层（A/B…）· 每层大概几张 · 每卡几秒（批量填，再逐卡改）
  - **人员表（staff 表）**：按模板列出职位，每个职位填人——可以选工会里的成员，也可以直接写一个名字（不在工会里的人 / 外包，标「外部」）；一个职位可以有几个人，一个人可以担几个职位；没人的职位显示「缺人」。职位和环节对上：开工时，填了人的职位 = 这些人自动报到对应环节。
- **模板项目**（选一个开局，再改）：
  - 「动画短片 · 标准」（照日本动画制作的常见分工，加上工会自己的分工）：
    - 统筹：制作人 · 监督（导演）· 制作进行（催进度、交接）· 设定制作（整理设定、发资料）· 文件导出整理
    - 前期：脚本（剧本）· 分镜 · 演出 · 人物设计 · 美术设定 · 色彩设计（色指定）· 设计稿（Layout）
    - 中期：原画 · 作画监督（原画监督）· 第二原画（清线）· 动画（中割）· 动画检查（中割检修）
    - 后期：上色 · 色指定检查 · 背景 · 美术监督 · 摄影（合成）· 摄影监督 · 特效 · 剪辑 · 音响（配音 · 音效）· 成片输出
  - 「视频 · 标准」（§3 视频组草案对应的职位）
  - 「从空白开始」
  - 每个职位写一句做什么（照上面的分组，一句话，中文）。

### 12.2 管理员改项目（开工以后）
- **环节**：加一个环节（名字 · 阶段 · 类型 过渡 / 枢纽 / 审核 · 粒度 · 单位 · Tn · 接在哪个环节后面 · 指示器文案）· 改 · 上下移动 · 停用（已经有交付的环节不能删，只能停用；停用的环节任务不再派）。新加环节时，已有的卡按它的位置生成任务（上游都通过的卡直接「可接」）。
- **把关（验收）**：每个环节有一个「验收」视图——这个环节所有卡的最终版并排列出来（链接 · 文件名 · 附图缩略图 · 谁做的 · 谁审的 · 质量系数），管理员可以：
  - 整个环节「验收通过」（`stage.accept`，记一条，环节节点上显示「已验收」）
  - 挑几卡「打回重做」（`task.reopen`：通过的任务回到退回，带意见，原来的活力点不扣，重做通过后按新的算）
  - 最后一个环节（成片输出）验收通过 = 项目完成。
- **不过的地方加时间、加卡**：
  - 延期：一张任务（`task.extend`：+小时 / +天 / 改到某天）· 一个环节的所有没完成的任务（`stage.extend`）· 整个项目的计划结束（`project.extend`），都记原因。
  - 加卡：在某一场里加几卡（`cut.add`：卡号接着往后排，或插在某卡后面用 `C005a` 这种；按模板生成这几卡的任务，上游已过的照样过不了——新卡从头走）· 给一卡加层 / 改张数 / 改秒数（`cut.update`，工作量和时限跟着变）· 停用一卡（`cut.archive`，不再派）。
  - 每次改都在项目时间线上留一条（谁、改了什么、为什么），成员的大厅「工会动态」里也看得到。
- 页面：项目总览右上「改项目」→ 项目设置（介绍 · 日期 · 结构 · 人员 · 环节）；环节节点点开的抽屉里加「验收」「延期」「加卡」入口；卡详情里管理员多「延期」「打回重做」「停用这一卡」。

### 12.3 验收（加进冒烟）
用「动画短片 · 标准」模板建项目 → 零日页填介绍、日期、关键日、结构（3 卡）、人员（2 个成员 + 1 个外部名字，留 1 个缺人）→ 开工 → 填了人的成员自动报到、能拿到任务单 → 加一个环节「分镜检查」接在分镜后面 → 加 2 卡 → 延期一张任务 → 某环节验收：打回 1 卡重做、其余验收通过 → 时间线上每一步都有记录 → 刷新还在 → 375 宽能用 → 控制台 0 报错。

## 13. 灵活性：人员指派 · 周期 · 随时发新任务

要解决的问题：灵活性。① 人员指派：管理员能给人指派职位，这个人也能自己去认领别的工作；② 周期与任务：每个步骤的周期能调，任何节点上（例如分镜）都能直接发新任务。参考日本动画的标准做法，目的是让流程真的做得下去。

参考的日本动画做法：制作进行 / 演出把卡分给原画师，原画师也会自己接卡；作画监督这类把关的位置是指定的；修正（リテイク）随时作为新的活发出去，挂在原来那一卡上；每个环节在项目排期上有自己的时间段（就是工会「项目规划表」那种按周的甘特图）。

### 13.1 人员指派（两条路都要有）
- **管理员指派职位**：在人员表或成员页给一个人指派一个或几个职位（= 环节），他就自动报到这些环节；能撤掉。指派的职位在成员卡上显示为「指派」。
- **管理员指派任务**：一张或一批（选几卡）任务直接派给某人（已有的「指派」照用），任务单上写「白鹭派给你的」。
- **成员自己认领别的工作**：成员不止能接自己职位的任务，**也能去认领别的环节「可接」的任务**——报到页和项目总览里都能点「认领」；第一次认领某个环节时自动给他加一条报到（熟练度默认 0，标「自己认领」）。上限照旧（同时最多几张）。
- **环节可以锁成「只给指派的人」**：管理员在环节设置里打开（默认：审核类环节——原画监督、中割检修、检查色指定——打开；其余关闭）。锁住的环节，没被指派的人看得到但点「认领」时提示「这个环节只给指派的人，找管理员」。
- 成员页显示两部分：指派的职位 · 自己认领做过的环节。

### 13.2 周期（每个环节在排期上的时间段）
- 每个项目的每个环节有**计划周期**：开始（第几周 / 日期）· 工期（几周 / 几天）。模板给默认值（按阶段排开），管理员能改；一周期几天在项目设置里改（默认 7）。
- 每个环节还能改**时限参数**：每单位小时 Tn · 时限系数（默认 1.5）· 最短时限（默认 4 小时）。改了只影响之后派出的任务；已经派出的任务用「延期」改。
- **项目排期视图**（照工会自己的「项目规划表」）：一行一个环节，按 前期 / 中期 / 后期 分组；横轴是周；每行画「计划工期」（浅色条）和「实际」（深色条：从第一张任务被接到最后一张通过，没完就到今天）和完成百分比；超出计划的部分用另一种颜色并写「超出 N 周」；今天那一周突出显示。管理员在这里直接拖条或改数字调整周期。下游计划开始早于上游计划结束时，这行旁边提示一句（只提醒，不拦）。
- 项目总览加一个切换：「流程」（现在的三关 + 网格）/「排期」（上面这个）。

### 13.3 随时发新任务（在任何节点上）
- 在任何一个环节节点（例：点开「分镜」）的抽屉里，管理员（和这个环节的审核员）能**发布新任务**：
  - 种类：**额外任务**（例：「补一张道具设定」）· **修正**（挂在某一卡上：「C003 分镜加一个镜头」，相当于リテイク）· **补设定**（挂在几卡上，照拍板结果补）
  - 填：标题 · 说明 · 挂哪几卡（可以不挂）· 工作量（单位照环节，或者直接给一个固定活力点）· 时限 · 派给谁（某人 / 放出来让人认领）· 谁审（默认这个环节的审核员）· 附图（资料库里选或直接贴）
- 新任务和别的任务一样走：认领 / 指派 → 交 → 审 → 活力点；它们**不挡流程**（不影响下游解锁），除非发布时勾了「这一卡要等它做完」（勾了，这卡的下游就等它通过）。
- 在网格里，有额外 / 修正任务的格子右上角多一个小数字（几件）；环节抽屉里列出这个环节的全部额外任务。
- 命令：`task.publish`（发新任务）· `task.assign`（指派，已有就照用）· `role.assign` / `role.unassign`（指派职位）· `stage.set_lock`（只给指派的人）· `stage.set_period`（计划周期）· `stage.set_rate`（时限参数）。被拒时中文原因（例：「这个环节只给指派的人」「工作量要大于 0」）。

### 13.4 验收（加进冒烟）
管理员给成员 A 指派「原画」职位 → A 自动报到原画 → 管理员把 C001–C003 原画直接派给 A → 成员 B（没这个职位）去认领中割的可接任务成功、自动多一条「自己认领」的报到 → 管理员把「作画监督」锁成只给指派的人，B 认领被拒、看到中文原因 → 在「分镜」节点发一张修正任务挂在 C002、派给 B、勾「这一卡要等它做完」→ C002 下游等它 → B 交、审核通过 → C002 下游解锁 → 改「中割」的计划周期和 Tn → 排期视图里计划 / 实际 / 超出都对 → 刷新还在 → 375 宽能用 → 控制台 0 报错。

## 14. 部署：境内画师必须能用

> 现在先把应用做好：§14.3（字体不连外网）已经做了；§14.4 的服务器暂缓，留作以后的参考。

要解决的问题：主要用户是华语画师，其中不少在中国大陆，部署方式要让他们打得开。

### 14.4 服务器（设计，还没做）
- **形状**：`server/`（Node 20 + TypeScript，不用框架或用最小的 http 路由；和网页共用 `src/domain` 的同一套纯函数命令）。Postgres 16。表：`worlds_store`（一个工会一行 + 快照 + head_seq，这一行也是写锁）· `journal`（只追加，`world_id + seq` 主键，`client_cmd_id` 唯一防重发）· `accounts`（工会 · 登录名 · scrypt 哈希 · 角色 · 连错次数 · 锁到 · 要不要改口令）· `invites`（token 的哈希 · 谁发的 · 能用几次 · 到期 · 给哪个角色）· `preview_links`（只读链接 token 的哈希 · 哪个项目 · 开着 / 关了）· `files`（sha256 · 大小 · 类型 · 谁传的 · 在哪个工会）。
- **一条命令怎么走**：浏览器先在本地跑（界面不等），带自己生成的 ID 发给服务器；服务器锁住那一行、重跑命令、追加日志、回新日志；被拒就回中文原因，浏览器退回服务器的样子。拉新：窗口在前台时每 3 秒一次，后台不拉。
- **离线优先**：没网时命令先排在本地（存起来），有网了按顺序发；界面上显示「还有 N 步没传上去」。
- **账号**（两种 + 只读链接）：
  1. 管理员建账号 → 服务器生成一次性的初始口令（只显示一次）→ 管理员私聊发给成员 → 成员第一次登录必须改口令。
  2. 邀请链接：管理员生成 → 选给哪个角色、能用几次（默认 1）、几天到期（默认 3）→ 成员打开链接，填昵称、设口令，进来；用完 / 到期失效；能提前作废。
  3. 只读进度链接：每个项目可以生成，不登录能看项目总览（三关 + 网格 + 排期），看不到账号、口令、成员页、评论原文以外的私人内容（成员只显示昵称）；能关掉。
  - 口令 scrypt 哈希（Node 自带 crypto）；会话 = HttpOnly · Secure · SameSite=Lax 的签名 Cookie（HMAC-SHA256，密钥从环境变量来），7 天；连错 5 次锁 1 分钟（记在数据库里）；写接口核对 Origin。
  - 预建的 `admin` / `member01` 照样能用（导入时带哈希），上线后管理员第一件事改口令。
- **文件**：先存服务器硬盘（`/data/files/<sha256>`，单个文件上限 50MB，总量在设置里显示），只给登录的成员；只读链接只给缩略图。以后接飞书时换成存飞书。
- **备份**：每天自动 `pg_dump` 一份到硬盘，留 14 天；管理员仍能导出 JSON。
- **两种模式自动认**：从服务器打开（有 `/api/health`）= 服务器模式；单文件版 / 没服务器 = 本机模式（现在的样子）。本机模式下做的工会能「传到服务器」（导入）。
- **部署包**：`deploy/` 里一个 `docker-compose.yml`（web + server + postgres + caddy）、`.env.example`（不放真值）、`install.sh`（一台全新的 Ubuntu 22.04/24.04 上一行跑完）、`README-部署.md`（中文：买服务器 → 买域名 → 实名 → 解析 → 登录服务器 → 跑一行 → 打开网址 → 改口令；每一步写清楚点哪里）。密钥由部署的人自己填，不进仓库。
- **测试**：服务器的单元测试 + 集成测试（CI 里起 postgres:16）：追加 · seq 连续 · 重发不重复 · 两个人同时改同一处只有一个过 · 快照来回 · 登录 / 邀请 / 只读链接 / 连错锁 · 离线排队再发。端到端：两个浏览器两个账号，一边交，另一边 3 秒内看到。

## 16. 中文 / 英文

要解决的问题：画师大多说中文，但分布在不同国家和地区，必须有英文界面。

- **两种界面语言**：中文（默认）· English。第一次打开按浏览器语言选（`zh*` → 中文，其他 → English），右上角 / 侧栏底部一个切换（「中 / EN」），记在这台设备上；登录后也跟着账号记。
- **所有界面文字走词典**（`zh` / `en` 两份，键名一样；少一个键测试就报错）：页面、按钮、空状态、提示、**命令被拒的原因**（数据层改成返回 `code + 参数`，界面按语言拼句子；中文原文保持现在的说法）、平台名、状态名、标签、模板里的环节名和职位名（模板自带中英两种名字；管理员自己起的环节名就是他写的那个）。
- **用户写的内容不翻译**：项目名（安娜的旅程）、卡号、意见、说明、昵称照原样显示。
- 日期、数字按语言显示（`10月23日 周五` / `Fri, Oct 23`），时间照旧走数据层时钟；英文的复数和语序要对（`1 task` / `3 tasks`）。
- 导出汇报（§15.3）的表头跟着当前语言；文件名也是。
- 英文文案：简单、直白、行业通用说法（Key animation · In-between · In-between check · Color design · Layout · Compositing · Retake · Settings sheet），写给画师看，不写成机器翻译腔。
- 视觉：英文更长，按钮、标签、网格表头不能溢出、不能截断成看不懂（检查 375 宽）。
- **验收（加进冒烟）**：中文 + Asia/Shanghai、English + UTC 两套各把每一页打开一遍；English 下页面上除了用户内容和示范数据里的项目名 / 昵称以外**没有一个汉字**（测试里扫可见文字）；切换语言后刷新还是那个语言；两种语言下命令被拒的原因都对；375 宽两种语言都不溢出；控制台 0 报错。

## 17. v1.1 · 项目按环节分层 · 零日一步一步开局

要解决的问题：在真实使用里，项目是从零开始一点点往后推的。项目页至少要清楚看到 1、2、3……每个环节走到哪、哪里已经彻底结束，能点进每个环节看人员和派发再去改；一个整体的「改项目」大页面太复杂，要按层拆开。

**原则**：三层，一层只管一件事——**项目（走到哪）→ 环节（谁在做、派了什么、交了什么、改这个环节）→ 卡 / 任务（具体一版）**。改什么就在它所在的那一层、就地改（小弹层），不再有一个「改项目」大表。

### 17.1 第一层 · 项目页 = 环节路线
- 项目页默认就是**环节路线**：环节按顺序编号 **1、2、3……N**，按 前期 / 中期 / 后期 分三段，一行一个环节（手机也是一行一个）。每行：
  - 编号 + 名字 + 类型小标（过渡 / 枢纽 / 审核）
  - **状态**，只有这几种，用字 + 颜色 + 图形同时表示：**还没到**（上游没完，锁住）· **可以开始**（上游完了，还没人接）· **进行中**（x / y 卡通过）· **待验收**（全部通过，等管理员验收）· **已结束 ✓**（验收过了）
  - 进度条（这个环节的卡：通过 / 待审 / 在做 / 可接）
  - 人：在这个环节做事的人的头像（最多 5 个 + 「+3」）；没人时写「缺人」
  - 计划 vs 实际（「计划 第 6–8 周 · 实际从第 7 周开始」），超出时写「超出 2 周」
  - 提醒（只在有的时候出现）：待审 N · 退回 N · 快超时 N · 缺人
- 页面顶上一行概要：「第 11 / 20 个环节 · 前期 6 个全部结束 · 中期进行到 中割 · 后期还没到」；三段各一个小进度。
- **已经结束的段**默认折叠成一行（「前期 · 6 个环节已结束 ✓ · 展开」），让人一眼看到现在在哪；当前在做的环节高亮。
- 两个环节之间悬停 / 点「＋」= 在这里插一个环节（小弹层：名字 · 类型 · 粒度 · 单位 · Tn，其余用默认）。
- 页内切换（同一个项目页里的标签）：**环节**（默认）· 卡 × 环节（原来的网格）· 排期 · 资料库 · 项目动态 · 项目档案。
- 点任何一行 → 第二层环节页。

### 17.2 第二层 · 环节页（新页面，`#/project/<id>/stage/<key>`）
- 页头：「第 N 个环节 · 名字」· 阶段 · 类型 · 状态 · 上一个 / 下一个环节的箭头 · 上游是谁、下游是谁（能点过去）。
- **概况**一块：这个环节的进度数字（通过 / 待审 / 在做 / 可接 / 锁住，每个数字能点，下面的列表就筛到那一类）· 计划 vs 实际 · 时限参数一行。
- **人员**一块：
  - 指派的人（来自人员表的职位）· 自己认领的人 · 审核员；每人一行：手上几张、通过几张、准时率
  - 动作就在这里：「指派一个人」（选成员 / 写外部名字）· 「撤掉」· 「换审核员」· 「只给指派的人」开关
- **派发**一块（这个环节的所有任务，按卡排）：
  - 每行：卡 · 层 · 状态 · 谁 · 第几版 · 时限
  - 每行的动作（小菜单）：派给… / 改派 · 延期 · 收回 · 打回重做 · 看这一卡
  - 多选几行 → 「派给某人」「延期」一起做
  - 「发新任务」按钮（额外任务 / 修正 / 补设定）；这个环节的额外任务单独列在下面
  - 枢纽环节多一块「派发下游」（原来的枢纽派发，填工作量 → 生成 / 解锁下游任务，显示大概要几个人、几天）
- **交付物**一块：每卡的最新一版（链接 · 附图缩略图 · 谁做 · 谁审 · 质量）；全部通过后出现「验收这个环节」（整体通过 / 挑卡打回）。验收过了，这个环节在路线上变「已结束 ✓」。
- **这个环节的设置**（默认收起，点「改这个环节」展开，就地改、就地存）：名字 · 类型 · 粒度 · 单位 · Tn · 时限系数 · 最短时限 · 计划周期 · 收什么 / 交什么 / 交到哪 · 停用（有交付的不能删）· 上移 / 下移。
- **这个环节的动态**（只列和这个环节有关的：派了谁、谁交了、谁审了、改了什么）。
- 手机：每块一张卡竖着排；派发列表每行可以展开看动作。

### 17.3 项目档案（取代原来的「改项目」大表）

### 17.4 零日：一步一步开局

- 新建（选模板）以后进**开局向导**，五步，每步一屏、一件事，顶上是步骤条（① 介绍 ② 日期 ③ 结构 ④ 人员 ⑤ 开工），能「上一步 / 下一步 / 先跳过」，随时离开、回来接着做（每一步存了就算数）：
  1. 介绍：名字 · 代号 · 一段介绍 · 封面图（可以没有）
  2. 日期：开始 · 计划结束 · 一周期几天 · 关键日（时间轴实时显示）
  3. 结构：几集几场几卡、每卡几层几张几秒（批量填，下面实时预览会生成哪些卡）
  4. 人员：按 统筹 / 前期 / 中期 / 后期 分组的职位，先显示「关键职位」（每个环节对应的那一个），其余收起；填人：成员或外部名字
  5. 开工：检查清单（缺什么、会生成多少卡多少任务、谁会自动报到）→「开工」

- 示范工会里放一个**刚开工不久**的示范项目，让人看到「从零往后推」的样子：例「（示范）星期三的猫」，前 2 个环节已结束 ✓、第 3 个进行中、其余还没到（编的示范内容，标「示范」）。原来的「（模板）动画短片」留着作零日的例子。

## 18. v1.1 · 交付物盘点：按命名先自动查、再人工复查 · 看项目以图为主

要解决的问题：看项目状态应该以图片预览为主。一个做到一半的项目开始用这个系统时，要回头核查每个 checkpoint 的交付物是不是真的交了、还差多少。办法：先按命名规范读一遍交付物，作为第一层简易检查，再由人复查。

**场景**：一个已经做到一半的项目（例：安娜的旅程，系统里的进度是照口头说法录的，没有对过文件）要开始用这个系统。管理员要：① 把已经交了的文件一次读进来；② 系统按命名规范自动对一遍（第一层）；③ 人看图复查（第二层）；④ 对上的写回项目（补录 / 核实）；⑤ 一眼看到还差多少。以后每隔一阵可以再盘点一次。

**原则**：先认名字、再看图、最后人拍板。**自动的只提示，不替人改项目**；写回项目一定是人点了「确认」以后，并且整批能撤销。

### 18.1 已经查实的事（在 7 个真实 .clip 上验证过）
- CSP（Clip Studio Paint）的 `.clip` 文件里**自带一张整张画面的预览图**，不用打开 CSP 就能读出来：
  - 文件开头 `CSFCHUNK` + 8 字节总长 + 8 字节；后面一块接一块：8 字节块名 + 8 字节长度（大端）+ 内容。块名有 `CHNKHead` · 很多 `CHNKExta`（图层像素）· `CHNKSQLi`（一个 SQLite 数据库）· 最后 `CHNKFoot`（长度 0）。7 个文件里 `CHNKSQLi` 都紧挨在 `CHNKFoot` 前面，大小 0.5–2.4 MB（整个文件 4–28 MB）。
  - SQLite 里：`CanvasPreview`（`ImageType` · `ImageWidth` · `ImageHeight` · `ImageData` = 一张 PNG，约 1472 宽、80–120 KB）· `Canvas`（`CanvasWidth` · `CanvasHeight` · `CanvasResolution` · `CanvasRootFolder`）· `TimeLine`（`FrameRate` · `StartFrame` · `EndFrame`，例 24 帧 / 秒 · 0–144 帧 = 6 秒）· `Layer`（`MainId` · `LayerName` · `LayerFolder` · `LayerFirstChildIndex` · `LayerNextIndex`；从根文件夹往下走能列出顶层文件夹，例「参考 · BG · 原画 · 修线 · 动画 · 黑框 · 标注 · 镜头框」）。
  - 所以：**只读文件尾部那一块（几 MB 以内），不读整个大文件**，就能拿到缩略图 + 画布大小 + 帧率 + 时长 + 顶层文件夹名。
- 真实文件名的样子：`ANDLC_EP01_SC001_CUT005_A_ANI_v04.clip` · `ANDLC_EP01_SC001_CUT014_A_ANI_v02第一次修改后.clip`（版本号后面带了字）· 同一卡 v02 / v02第一次修改后 / v03 三个文件 · 同名 `.rar` 压缩包；文件夹 `/EP01/ANI/SC001/CUT005/`。
- **真实文件和它们的缩略图只在使用者自己的设备上用**：不进仓库、不进示范数据、不进测试。测试和示范一律用代码生成的假文件（§18.9）。

### 18.2 入口和步骤
- 项目页多一个标签「**盘点**」（管理员 · 审核员看得到），页面 `#/project/<id>/audit`；项目档案和环节页的交付物块里也有「盘点交付物」入口（从环节页进来时默认只看这个环节）。
- 盘点页顶上：**还差多少**一块（§18.6）+ 历次盘点的列表（日期 · 谁 · 读了多少 · 写回了多少 · 能打开 · 能撤销）+「开始一次盘点」。
- 一次盘点四步（步骤条，和零日向导一个样子，能离开再回来接着做）：**① 放进来 → ② 自动查 → ③ 人工复查 → ④ 写回项目**。

### 18.3 ① 放进来（三种办法，可以混着用，同一次盘点里能多次添加）
1. **拖一个文件夹**（或「选文件夹」）：整棵文件夹树读进来，记下每个文件的路径（拿来对「放没放对文件夹」）。也能拖 / 选很多个文件。
2. **粘贴文件名列表**：从飞书文件夹、QQ 群文件、网盘的列表里整段复制粘贴（只有名字，没有文件）。每行里只要能找到像规范文件名的一段就收（前后的大小、日期、上传人等字都忽略）；能认出 `/EP01/ANI/SC001/CUT005/文件名` 这种整条路径。没有文件的条目没有缩略图，标「只有名字」。
3. **压缩包**：`.zip` 读里面的文件名列表（读 zip 末尾的目录就够，不用解压）；`.rar` / `.7z` 只读外面的名字（写明「压缩包里面看不了」）。
- 可选：这一批的「放在哪」（贴一条飞书 / Google Drive / Dropbox 文件夹链接，照 §15.1 认平台），之后每条都带着这个链接。
- **存什么**：默认「**只存名字和缩略图（推荐）**」——文件本身不进浏览器，只存名字 · 路径 · 大小 · 修改时间 · 缩略图 · 读出来的信息。另一个选项「小图连原图一起存」（只对 20 MB 以下的图片，和资料库共用存储，存储页能看到占了多少）。
- 缩略图：图片和 .clip 预览缩到长边 640 像素再存（IndexedDB，按内容的 SHA-256 认，和资料库同一套）。
- 「指纹」= 大小 + 修改时间 + 缩略图的 SHA-256（**不为了算指纹去读整个大文件**），拿来认重复和「比上次盘点多了什么」。
- 读取：一次最多同时读 4 个；进度条（读了 x / y）· 能取消；500 个文件、其中 50 个 20 MB 的 .clip，在普通笔记本上 1 分钟内读完；断网能用。

### 18.4 读名字（命名规范 v1.0：`[项目]_[集数]_[场景]_[镜头]_[层级]_[流程]_[版本]`）
- 先整理：去掉扩展名（认 `.clip.rar` 这种双扩展名）· 全角下划线 / 全角字母数字转半角 · 去掉前后空格。
- **按 `_` 切开、按样子认每一段**（不死套一个正则，这样才能说清楚哪里错）：项目代号（第一段）· `EP01` · `SC001` · `CUT005`（插进去的卡 `CUT005a`）· 层级（A B C … · BG · PROP · FX）· 流程代码（取这个项目各环节自己的文件代码：PLAN · SCR · STB · ART · COL · LO · H · CLN · ANI · CMP · BG · SND · FIN，管理员改过的照改过的）· 版本 `v04`。版本后面多出来的字（「第一次修改后」「_final」「改」）收下来，算这一版的「备注」。
- 项目级的文件（剧本 · 分镜 · 设定 · 色指定）没有场景 / 镜头 / 层，例 `ANDLC_EP01_STB_v03.pdf`，照样认。
- **流程代码 → 环节**：一个代码只对应一个环节的直接对上；**几个环节共用一个代码**的（`H` = 原画 / 原画监督 · `ANI` = 中割 / 中割检修 / 上色 / 上色检查 … · `CMP` = 导出 / 合成 / 特效），先给一个「最可能的环节」：① 系统里有哪一版的规范文件名和它一样（同卡 · 同层 · 同代码 · 同版本）→ 就是那一版的环节；② 没有的话，取这一卡在系统里**还没通过的、最早的**那个；都通过了就给最后一个。.clip 的顶层文件夹名当提示显示（例「文件里有：原画 · 修线 · 动画 · 色」），**只提示，不自动定**。复查时能一键改，也能「这一批 ANI 都算 中割」。
- 每个文件得出：项目 · 集 · 场 · 卡 · 层 · 流程 → 环节 · 版本 · 备注 · 问题列表 · 是不是这个项目的。

### 18.5 ② 自动查（第一层）
**名字和放的地方**（每条问题都是一句人话，带「建议改成」）：
- 项目代号不对：差一两个字母的（`ANLDC`）提示「是不是 ANDLC？」；完全不一样的归到「**不是这个项目的**」，单独一组，不参与统计。
- 没补零：`CUT5` →「应写成 CUT005」（照样认出来）；大小写不统一（`cut005`、`V04`）同理。
- 不认识的流程代码 / 层级：列出来，给最像的那个（`ANM` →「是不是 ANI？」）。
- 顺序不对（`CUT005_SC001`）· 少一段（没有版本号 / 没有层）。
- 卡不在这个项目的卡表里（「CUT021 不在卡表里，这个项目一共 14 卡」）→ 复查时可以「加这一卡」或「不要」。
- 层不在这一卡的层里。
- 放错文件夹（拖文件夹进来时）：名字是 CUT006、放在 `/CUT005/` 里；流程是 ANI、放在 `/LO/` 里。
- **同一版有两个文件**（`v02` 和 `v02第一次修改后`，名字不一样、读出来是同一版）→ 复查时选哪个算数。名字一样只是扩展名不同的（`…_v04.clip` + `…_v04.rar` + `…_v04.png`）**不算问题**，合成一版的几种格式（缩略图取能读出图的那个）。
- 版本号后面带了字 → 「建议把『第一次修改后』改成下一个版本号 v03」（只提醒）。
- 版本跳号（有 v01 v02 v04，没有 v03）→ 只是信息。
- 认不出的文件（`.DS_Store`、随手的截图……）归到「认不出」，可以手动归到某一卡某一环节，或者不要。

**和系统里记的对一遍**（这是「是不是真的交付了」的那一步），每个 卡 × 环节 × 层 得出一种结果：
| 结果 | 意思 |
|---|---|
| **对上了** | 系统里记着交了 / 通过了，也找到了文件，版本对得上 |
| **有文件、系统里没记** | 补录候选（系统里还是「可接 / 在做 / 锁住」，但文件已经有了） |
| **系统说交了、没找到文件** | 要问清楚：文件放在别处，还是其实没交 |
| **文件比系统新** | 系统记的是 v04，盘点看到 v05 |
| **缺** | 系统里没交，也没找到文件 |

**文件里读出来的信息**（.clip / 视频才有，只显示，不算错）：画布大小 · 帧率 · 时长 · 顶层文件夹名。两条轻提示：时长和卡表里写的秒数差得多（「文件 6.0 秒，卡表写 5 秒」）；画布大小和同一批大多数不一样（有的卡本来就是长画布，所以只提示）。

自动查完给一行总结：「读了 126 个 · 认出 118 · 对上 71 · 有文件系统没记 23 · 系统说交了没找到 9 · 有问题 15 · 不是这个项目的 3 · 认不出 5」，每个数字能点，下面就筛到那一类。

### 18.6 以图为主（盘点页 · 项目页 · 环节页 · 卡详情都用）
- **交付物墙**（盘点页 ② ③ 和项目页的「卡 × 环节」都用它）：一行一卡，一列一环节（只放有画面的环节，项目级环节放在最上面一行），每格是那一卡那一环节**最新一版的缩略图**；格子右上角一个状态小标（字 + 颜色 + 图形）：**已核实 ✓**（人看过对上了）· **待复查**（名字对上了，还没人看）· **没文件**（系统说交了但没找到）· **有问题 ⚠** · **缺**（空格子画斜线）。看一眼就知道哪里空着。格子大小能调（小 · 中 · 大），能切回原来的文字网格。
- 点一格 → 看图器，左右键翻同一卡的上一个 / 下一个环节（LO → 原画 → 中割 → 上色……，看「是不是真的往前推了」）；上下键翻同一环节的上一卡 / 下一卡；同一卡同一环节的几个版本在底下一条缩略图里。
- **项目页的环节路线**（§17.1）每一行右边加一条缩略图：这个环节最新交的几张（最多 6 张 + 「+8」），点开看图器；这一行的提醒里多一个「缺 N 卡」「待复查 N」。
- **环节页的交付物块**（§17.2）默认是这一环节的交付物墙（一卡一张大缩略图），补录的标「补录」，核实过的标「已核实」。
- **卡详情**：这一卡从前到后每个环节的缩略图排成一条（胶片条）。
- **还差多少**（盘点页顶上，项目页概要行也写一句）：按环节一行——应交（卡数 × 层，项目级环节按集）· 已核实 · 待复查 · 没文件 · 有问题 · **缺**，一行一条进度条；最上面一行是全项目合计。点一格 → 交付物墙筛到那一类。

### 18.7 ③ 人工复查（第二层）
- 复查队列，排序：有问题的 → 有文件系统没记的 → 系统说交了没找到的 → 文件比系统新的 → 对上了的（最后）。
- 每条：**大缩略图**（没有图的显示文件类型 + 「只有名字」）· 同一卡上一个环节的缩略图并排（对照着看「是不是真的做了」）· 文件名切开显示（项目 / 集 / 场 / 卡 / 层 / 流程 / 版本，有问题的那一段标出来）· 问题一句话 · 系统里现在记的状态 · 建议的归属（卡 · 环节 · 层 · 版本）。
- 动作：**确认** · **不对**（选一个原因：不是这一卡 / 不是这个环节 / 是旧的 / 没做完 / 其他 + 一句话）· **改归属**（改卡 / 环节 / 层 / 版本，改完算确认）· **跳过**。键盘：`1` 确认 · `2` 不对 · `3` 改归属 · `→` 跳过。手机上也能做（一屏一条，按钮在下面）。
- 「对上了」的那一组可以**一次全部确认**（先看一眼缩略图墙，能取消掉几张再确认）。
- 「系统说交了、没找到文件」的：能「文件在别处」（贴一条链接或写一句，算核实）或者「确实没交」（→ 照 §12.2 打回重做那一卡那一环节）。
- 「不对 · 没做完」的，如果系统里那一环节已经通过 → 提示「要不要打回重做」（不自动打回）。
- 复查是谁、什么时候做的都记下来；两个人可以分着复查同一次盘点（同一台设备上切换身份）。

### 18.8 ④ 写回项目
- 写回前列一张清单：会**核实** N 版 · **补录** N 版（N 个任务变成「通过」）· 打回 N 个 · 加卡 N 张 · 不动 N 条。点「写回」才改项目。
- **核实**：在那一版上记「已核实（哪次盘点 · 谁 · 什么时候）」，状态不变。
- **补录**：给那个任务记一版「补录」的交付（文件名 · 路径 / 链接 · 缩略图），任务变「通过」，下游照常解锁。补录的版本在时间线、审核记录、导出里都标「补录」。
  - 谁做的：默认「不记人」；可以给一卡或一批选一个成员 / 外部名字。
  - 活力点：默认**不记**（以前的已经在工会的活力点统计表里了）；勾「按规则给做的人记活力点」才记（要选人和质量系数，算式照 §1 的计分规则、照审核台那样公开显示）。
- **文件比系统新**：选「记成新的一版」（补录一版）或「不管」。
- 整批写回在项目动态里是**一条**（「10/24 盘点：核实 71 · 补录 23 · 打回 2」，能展开）。
- **撤销这次盘点**：这一批写回的东西之后没人再动过，就能整批撤销；有人动过的那几条列出来，不撤。
- 再盘点一次时，对比上一次：「比上次多了 12 个文件 · 3 个文件不见了 · 5 个版本更新了」。

### 18.9 数据和代码
- 新的表（照原来的做法：命令 → 变更 → 日志，能重放，有完整性检查）：`audits`（项目 · 谁 · 什么时候 · 来源 · 放在哪的链接 · 步骤）· `auditItems`（名字 · 路径 · 大小 · 修改时间 · 指纹 · 缩略图文件 id · 读名字的结果 · 问题 · 文件信息 · 建议归属 · 复查结论 · 写回了什么）。交付（submissions）多两个字段：补录（哪次盘点）· 核实（哪次盘点 · 谁 · 什么时候）。命令被拒的原因照 §16 走 `code + 参数`。
- 读名字、对系统、算「还差多少」都在数据层，写成纯函数，单元测试一张表一张表地测（每种问题至少一个例子）。
- **.clip 读取**：先读文件最后一段找 `CHNKSQLi`（照 §18.1 的结构），找不到再一块一块地往后走（只读每块的 16 字节头）；读 SQLite 用**自己写的只读小读取器**（读页头 · 表的 B 树 · 溢出页 · 记录解码，只够读这几张表；大约几百行，单元测试覆盖），不要为这个引进约 1 MB 的 sql.js（单文件版会大很多）。现在用的就是自己写的读取器。读不出来就当「只有名字」，不报错、不卡住。
- 其他格式：png / jpg / webp / gif 直接缩略；`.psd` / `.psb` 读文件里自带的缩略图（图像资源 1036，JPEG），读不到就只有名字；`.mp4` / `.webm` / `.mov`（浏览器能播的）取第 1 秒一帧 + 读时长；`.zip` 读目录；其他只读名字。
